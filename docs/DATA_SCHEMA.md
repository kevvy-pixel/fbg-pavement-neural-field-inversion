# Private input-data schema

All experiment scripts read `Response_Matrix_Table.csv` from the repository
root. The file is private and must not be committed.

## Required columns

| Column | Meaning |
|---|---|
| `case_id` | Unique loading-condition identifier |
| `sensor_id` | FBG measurement-point identifier |
| `x_cm`, `y_cm` | Sensor coordinates in centimetres |
| `layer` | Structural layer, such as `Asphalt` or `Soil` |
| `direction` | Longitudinal or transverse sensing direction |
| `delta_lambda_resp_nm` | Baseline-corrected wavelength response in nanometres |
| `load_type` | Loading-condition category |
| `load_kg` | Applied load in kilograms |
| `p1_x`, `p1_y` | Coordinates of the first loading point |
| `p2_x`, `p2_y` | Coordinates of the second loading point |

For a single-point case, the second-point fields may be missing values, but the
columns must still exist.

## Validation

From the repository root, run:

```matlab
run('check_data_schema.m')
```

The validator checks the file, required headers, row count, case count, layers,
and sensing directions. It does not start model training.

## Provenance

The response matrix is generated by the preceding FBG data-processing project:

[`fbg-multilayer-pavement-modeling`](https://github.com/kevvy-pixel/fbg-multilayer-pavement-modeling)

The private dataset and generated model artifacts are deliberately excluded
from this repository.
